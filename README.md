# 🦁 ФОРТОРИУМ — интерактивная лаборатория работы с ИИ

Демо-платформа, иллюстрирующая эволюцию способов работы с ИИ: от простых промптов
до луп-инженеринга (автономных циклов агентов) и граф-инженеринга. Каждый уровень
эволюции — не слайд, а работающий механизм, который можно запустить и потрогать.

> Приложение живёт на https://fortorium.vercel.app/

---

## Уровни эволюции (вкладки приложения)

| Уровень | Что демонстрирует | Где смотреть |
|---|---|---|
| 1. Промт-инженеринг | Команда ботов-агентов (продюсер → сценарист → художник…) превращает идею в сценарий | «🎮 Демо» |
| 2. Контекст-инженеринг | Память проекта, роли агентов, управление контекстным окном | «🤖 Агенты» |
| 3. Харнес-инженеринг | SVG-конвейер из 10 специализированных агентов (палитра, фон, перспектива…) | «🎨 SVG» |
| 4. **Луп-инженеринг** | Цикл План → Действие → Наблюдение → Коррекция, чистые агенты с файловой памятью | «♾️ Луп» |
| 5. **Граф-инженеринг** | Ветвящийся граф агентов с маршрутизатором и рёбрами самокоррекции | «♾️ Луп → 🕸️ Граф» |

## ♾️ Луп-инженеринг (ядро платформы)

### Три обязательных условия автономности

1. **Чёткий критерий остановки** — лимит витков, порог качества, бюджет токенов.
   Без них цикл «пережуёт» весь бюджет и не остановится.
2. **Безопасная среда (песочница)** — цикл пишет только в файлы памяти проекта,
   никаких писем, платежей и продакшена.
3. **Валидатор** — двойной барьер: детерминированные скрипт-проверки +
   независимый LLM-критик с баллом 0–10.

### Чистые агенты и файловая память

Агенты «чистые»: нулевой диалоговый контекст, каждый виток они читают состояние
из файлов памяти (`state.json`, `iteration-N.json`, `final.json`). Память не
переполняется — её всегда можно осмотреть, перенести, восстановить.

- **v6.0**: память живёт в **Vercel Blob** (персистентно на проде), при отсутствии
  токена — автоматический фоллбэк на локальную ФС (локальная разработка).

### Три долга автономности

Считаются в реальном времени и показываются шкалами:
токены/**деньги** (демо-тариф 2.5 ₽ за 1К токенов), **время** (латенси витков), **техдолг**
(переделки, проваленные проверки).

### Внутренний и внешний круг

- Внутренний круг (ИИ) крутит витки автономно.
- Внешний круг (человек) стоит у **ворот одобрения**: без авто-режима после каждого
  витка цикл ждёт решения — Принять / Переделать / Остановить.

### Вложенные лупы (луп над лупом)

Мета-луп = **надзиратель**: сам текст не пишет, а управляет дочерними лупами —
планирует подцели, продвигает детей, агрегирует результаты, перезапускает слабых.
Дети — внутренний круг, ворота мета-лупа — внешний. Живое SVG-дерево вложенности
показывает надзирателя, ветви-детей и рёбра самокоррекции.

## 🗂 Портативность сборок: экспорт → импорт → галерея

**Сборка** — это экспортный документ run-а, содержащий не только результат, но и
ВСЮ файловую память (журнал витков, долги, состояния агентов). Принцип:
*состояние агента — его файлы; переносишь файлы — переносишь агента.*

### Экспорт

- **Одиночный цикл**: `fortorium-loop-assembly v1` — JSON (полная сборка + файлы памяти
  инлайном) и Markdown-паспорт. Кнопки в тулбаре статуса и у лучшего черновика.
- **Надзиратель**: `fortorium-supervisor-assembly v1` — дерево детей с их состояниями
  и памятью, журнал мета-витков, агрегированные долги, статистика.
- Файлы памяти >256 КБ экспортируются метаданными (без содержимого).
- Каждая сборка хранит **sceneRef** — ссылку на сцену демо-режима, из которой цикл
  стартовал (происхождение артефакта для трассировки).

### Импорт (воспроизведение run из JSON)

Кнопка «⬆️ Импорт сборки из JSON» в «♾️ Цикл» и «🪆 Вложенные лупы»: файлы памяти
записываются обратно в хранилище под теми же runId — run воскрешается в исходном
виде. Завершённый run снова виден и экспортируем; **незавершённый можно продолжить** —
чистые агенты не заметят переезда.

### Галерея сборок («♾️ Луп → 🗂 Галерея»)

Публичная библиотека сборок внутри сайта:

- **↗️ В галерею** — публикация прямо из тулбара экспорта (повторная публикация
  того же run обновляет запись — upsert по runId);
- **⬆️ Опубликовать сборку из файла** — можно выложить и чужой экспортный JSON;
- **⬆️ Восстановить run** — импорт из галереи одним кликом, восстановленный run
  открывается в своей подвкладке и продолжается;
- **↩️ В демо-сцену** — лучший текст сборки возвращается в демо-режим: обновляется
  сцена-источник по sceneRef (или добавляется новой сценой / создаётся сценарий);
- **⬇️ JSON / паспорт .md** — скачивание; **🗑** — удаление записи.

Хранилище галереи — тот же memory-store (Vercel Blob / локальная ФС).

## 🎮 Связка демо-режима с лупом

На карточке любой сцены раскадровки:

- **♾️ Прогнать через луп** — цикл дорабатывает текст сцены (initialDraft);
- **🪆 Вложенный луп** — надзиратель разворачивает сцену в микросцены;
- результат возвращается в сцену кнопкой одобрения, сцена получает бейдж
  «улучшено лупом», рядом появляются ссылки на сборку (`📦 ⬇️JSON / ⬇️.md`).

Обратный путь: галерея сборок → «↩️ В демо-сцену».

## API

| Метод и путь | Назначение |
|---|---|
| `POST /api/loop` | `init` / `step` / `accept` / `stop` / `reset` / `import` |
| `GET /api/loop?runId=…` | состояние run-а |
| `GET /api/loop?runId=…&export=json\|md` | экспорт сборки цикла |
| `POST /api/loop/meta` | `init` / `step` / `accept` / `stop` / `reset` / `import` |
| `GET /api/loop/meta?metaRunId=…&export=json\|md` | экспорт сборки надзирателя |
| `GET /api/loop/gallery` | список записей галереи (+ бэкенд хранилища) |
| `GET /api/loop/gallery?id=…[&download=json\|md]` | запись / скачивание сборки |
| `POST /api/loop/gallery` | публикация: `{runId}` / `{metaRunId}` / `{doc}` |
| `DELETE /api/loop/gallery?id=…` | удаление записи |
| `GET /api/loop/memory?runId=…` | файлы памяти + бэкенд |
| `POST /api/loop/graph` | маршрут по графу агентов |
| `GET /api/version` | версия приложения |

Безопасность: все входные `runId` / `metaRunId` / id записей галереи проходят
`sanitizeRunId` (латиница/цифры/дефис/подчёркивание) — path traversal исключён;
форматы сборок валидируются перед импортом и публикацией.

## Запуск и деплой

```bash
bun install
bun run dev        # локальная разработка (память на ФС — cwd/memory)
bun run build && bun run start
```

Деплой — Vercel (main пушится автоматически). Для **персистентной** памяти и
галереи на проде подключите Blob Store:

> Vercel Dashboard → проект → Storage → Create Database → **Blob** → Connect to Project

После этого `BLOB_READ_WRITE_TOKEN` появится у проекта автоматически, память
переключится на Blob без изменений кода (бейдж хранилища в UI покажет
«Vercel Blob (персистентно)»).

LLM работает через Z.AI SDK; без ключа платформа не падает — агенты переходят
в оффлайн-режим с пометкой degraded, скрипт-проверки продолжают работать.

## Структура (луп-часть)

```
src/lib/loop/
  types.ts              # типы ядра: LoopTask, LoopState, MetaState, SceneRef…
  loop-engine.ts        # виток: план → черновик → скрипт-проверки → критик
  validator.ts          # скрипт-проверки + LLM-критик
  debts.ts              # три долга (токены/деньги, время, техдолг)
  meta-loop.ts          # мета-луп: надзиратель над дочерними лупами
  graph-router.ts       # граф-инженеринг: маршрутизатор по графу агентов
  memory-store.ts       # память: Vercel Blob + фоллбэк на ФС
  loop-export.ts        # сборка одиночного цикла (fortorium-loop-assembly v1)
  supervisor-export.ts  # сборка надзирателя (fortorium-supervisor-assembly v1)
  assembly-import.ts    # восстановление файлов памяти из сборки
  gallery.ts            # галерея сборок: публикация/upsert/список/удаление
src/app/api/loop/       # REST: цикл, мета-луп, галерея, память, граф
src/components/loop/    # LoopStudio, NestedLoops, MetaLoopTree, AssemblyGallery…
```
